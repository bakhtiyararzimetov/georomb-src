# Как работать с кодом GeoRomb

Проект закрытый (см. [LICENSE](LICENSE)). Вносить изменения можно только по договорённости с владельцем.

## Подготовка

```bash
nvm use            # Node.js 26 — версия в .nvmrc
npm install
cp .env.example .env
npm run dev        # приложение в браузере: http://localhost:5173
```

Подробнее: [docs/development.md](docs/development.md).

## Ветки и коммиты

- `main` — то, что уже выпущено или готово к выпуску. Напрямую в неё не коммитим.
- Каждая задача делается в своей ветке: `feat/…` — новое, `fix/…` — исправление, `docs/…` — документация, `chore/…` — инфраструктура.
- Сообщения коммитов пишем по-русски, в повелительном или назывном виде: «Раскрой: учитывать пропил у армирования».
- Pull Request в `main` вливается, только когда CI зелёный.

## Перед Pull Request

```bash
npm run typecheck  # типы во всех частях: app, backend, server
npm test           # тесты сервера API
npm run build      # сборка приложения
```

CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) запускает те же команды.

## Правила кода

- TypeScript в строгом режиме, без фреймворка во фронтенде. Стиль смотрите в соседнем коде: отступ 2 пробела, комментарии по-русски, объясняют «почему», а не «что».
- Расчёты (`app/src/model`) не трогают DOM. Тогда их могут использовать и приложение, и сервер.
- Формат данных в [app/src/types.ts](app/src/types.ts) совпадает с тем, что уже сохранено у пользователей. Поля и значения не переименовываем, новые поля добавляем только необязательными.
- Новое поведение и исправления — с тестом: сначала тест, который падает, потом код.
- Никогда не добавляйте в git `keys/`, `backend/data/`, `*.jks`, `.env` (см. [SECURITY.md](SECURITY.md)).
